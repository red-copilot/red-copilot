### QA-04 [~] continuous — Architectural hygiene
Deliver: enforce import direction; no redundant wrappers, duplicate lifecycle logic or premature infrastructure. Document public contract migrations.
Accept: dependency checks in CI; PRs that add modules justify ownership, public API and tests.

The AST-based import guard checks imports nested inside functions and is part of the regular pytest suite. It rejects infrastructure dependencies from domain/runtime layers (FastAPI, Starlette, Docker, subprocess, httpx, and TSec SDK), and rejects web-server/Docker imports from benchmark adapters; a negative fixture proves the guard reports these violations. [Architecture documentation](../architecture.md) describes module ownership, dependency direction and migration constraints. Validation on 2026-10-09: architecture tests passed (2), full suite passed (356 passed, 3 skipped), Ruff, compileall and `git diff --check` passed. Docker-dependent tests were skipped because Docker is unavailable. This remains continuous: CI execution evidence and per-PR module ownership/public API justification are still required; no blanket completion claim is made.

The import guard also recognizes `importlib.import_module()` and `__import__()` through imported, assigned and `getattr` aliases, including a chained `__import__("importlib").import_module(...)` form; it resolves literal string concatenation and rejects unresolved dynamic targets from restricted layers. Calls to `eval` or `exec` through direct names, imported aliases, or `builtins` module/`getattr` aliases are rejected as dynamic code execution. Negative fixtures cover these paths, and the current restricted modules contain no such calls. Validation on 2026-10-09: architecture tests passed (4); full suite passed (442 passed, 4 skipped); Ruff, compileall, architecture checks, and `git diff --check` passed. Docker-dependent acceptance remains unexecuted in this environment.

Architecture-guard re-audit found that a `getattr(importlib, "import_module")` or `getattr(builtins, "__import__")` callable assigned to an alias was not added to the dynamic-import alias set, allowing a later call to bypass the direction check. Added a failing regression for both forms; the guard now follows these aliases and reports the resolved forbidden module targets. Architecture tests passed (4); Ruff passed.
